# Stage I4 c3 operational surface

This successor closes the six grouped R5 passive findings as one engineering
batch. It does not authorize application contact or shadow execution.

## Human path

1. Verify an exact trusted review archive against its external review policy.
2. Build the complete relation/case map and execution context.
3. Validate the pinned AOK HeadlessRunner binding. If the AOK capability lattice
   is absent, preserve `NATIVE_RUNNER_UNAVAILABLE`; UCM must not substitute an
   executor.
4. Build the sealed run contract. The effect membrane permits only pure or
   read-only preparation and still records `execution_authorized: false`.
5. Record G1 Sentinel, native dispatch, G2 Witness, and G3 Diagnostic as one
   operation. A lost response is retried under the same event identity. An
   uncertain dispatched outcome blocks redispatch until operator resolution.

## Agent path

Use `ucm capabilities`, then the four c3 capability surfaces. Agent, CLI, and
direct library calls return the same canonical records. The realization
contract is the conceptual interface; exact capability schemas are the calling
interface.

## Observability

The JSONL stream and compact summary report phase, case/test progress, counts,
remaining work, and current status. They are best effort and excluded from all
roots and verdicts. Missing or unwritable progress can never turn successful
work into a refusal.

## Native boundary

AOK owns HeadlessRunner execution, leases, provider selection, and effect
custody. UCM pins the acknowledged runner and contracts, validates preflight
and terminal receipts, and refuses when the native runner is unavailable. No
fallback executor is present.
