# Agent start

Use the pinned loop in `spec/AGENT-LOOP-CONTRACT.json`: orient, bind the exact
subject, validate or compile, plan, cross the Operational Gateway for effects,
then export the journal. Carry exact roots in tool results. Treat chat summaries
and progress JSONL as non-authoritative. The reference `AgentToolAdapter`
refuses a capability/profile registry mismatch before exposing a surface.

Treat this file and `python tools/ucm.py orient` as orientation, not authority.

## Operating sequence

1. Verify `release/SOURCE-MANIFEST.json` and `release/RELEASE-IDENTITY.json`.
2. Call `orient` and `capabilities`; use each row's availability, route, schemas, effect, and readiness state rather than inferring surfaces from filenames. Default discovery contains current routes only.
3. Bind requests to exact contract and subject roots.
4. Use the Realization Space Engine to describe variation and selection without changing subject identity. `PASS_ADMISSIBLE` means axis domains and every supported hard constraint were evaluated; it does not mean lowering or deployment occurred.
5. Use UCL and Tessera projection for executable intent and obligation continuity.
6. Accept a proof only after the Native Proof Kernel rechecks its certificate against the exact subject.
7. Use Project Intelligence before preparing a plan. Unknown impact selects broader testing.
8. Keep plan preparation distinct from execution. `BUILD_PORTABLE_PROFILE` is a separately staged operation, and the Autonomous Project Manager has no production authority.
9. Preserve typed refusals, terminal receipts, and lineage roots across sessions.
10. For application integration, validate and compile the AMCAS contract,
    create or reopen the durable campaign, and use its content graph and plan.
11. Import a user's MosaicID passport only against the expected public ID. Use
    a distinct agent/session identity and a fresh, durably consumed challenge.
12. Stream progress for visibility, while treating only the journal and bound
    receipts as evidence. Export software and journal archives separately.
13. In a portfolio, import exact composition declarations through the campaign CAS.
    Match an edge only after provider invitation and consumer acceptance agree
    on provider, interface ID, and schema root. Rejections require a provider
    successor; never silently rewrite a session's declaration.
14. Do not select a predecessor route from memory or from a filename. If exact
    replay requires one, call `legacy-capabilities`, select the explicit
    `COMPATIBILITY` profile, and record the current replacement named there.
15. For an external execution adapter, discover and bind the exact pack before
    proposing dispatch. For UGEL, begin with `ucm ugel-orient`, preserve its
    domain root separately from UCM's semantic root, pass the declared proposal
    through Pippi, and use only executor-signed receipts at G2/G3. A pack
    binding is not a grant and UCM never selects the executor.

## Portable adaptation sidecar

The slim sidecar in `dist/` can travel beside this UCM core. It pins the exact
system and capability registries, carries the integration skill and templates,
and forwards only the bounded integration command set. Its progress output is
nonsemantic; UCM's journal and G1/G2/G3 receipts remain the evidence surface.

## Global ceiling

Every public surface is pure computation or read-only unless a separate contract explicitly says otherwise. This release remains `INFORMATION_ONLY`, `authority_effect: NONE`, `real_a5: false`, and `g0: CLOSED`.

Raw keys, tokens, passwords, private seeds, and unbound external commands are not valid request data.
