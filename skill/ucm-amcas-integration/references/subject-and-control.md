# Subject and control-plane boundary

Bind one exact subject before integration:

- `IMMUTABLE_ARCHIVE`: the supplied archive bytes are the subject.
- `IMMUTABLE_SNAPSHOT`: the selected directory bytes are frozen as a snapshot.
- `WORKING_BASELINE`: the selected bytes and Git observation form a mutable
  engineering baseline. Later changes require a new binding.

Do not derive a source root from a conversation, title, project name, or
unavailable path.

Inventory every native plane that controls meaning, effects, identity,
jurisdiction, validation, repair, testing, deployment, or receipts. Exactly one
plane owns application semantics. An effect class has one executor. UCM is an
observer and governor here, never the application's executor. RETAIN is the
default. ADAPT adds a boundary without changing native meaning.
REPLACE_AFTER_EQUIVALENCE requires a rooted correspondence result.

The AMCAS v0.2 `integration_boundary` must match the separately verified
control-plane disposition exactly.
