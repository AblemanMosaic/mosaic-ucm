# Contributing

Changes must preserve the authority ceiling, typed refusals, deterministic roots, and compatibility boundaries. Add focused tests first, run the public suite, and rebuild release artifacts twice to check determinism. Changes to semantics, canonicalization, proof rules, authority, custody, or the cold-boot format require an explicit migration note and full qualification.

Do not commit generated release archives, credentials, private keys, local host observations, or predecessor evidence ZIPs.
