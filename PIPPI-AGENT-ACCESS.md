# Agent access to P/PPI

Begin with `pippi standards` and `pippi pipeline-model`. Pin their roots in the
turn opening, then use `standard-explain`, `transition-explain`, and
`context-explain` instead of reconstructing rules or pipeline state from chat.
Every implementation step names one acceptance case. A transition marked as
CCP-required remains held until the complete independently anchored current-use
evaluation validates and admits the exact subject. A caller-provided `ADMIT`
label is never sufficient.

Collaborator handoffs use a public MosaicID passport, DKN namespace and epoch,
stable nonce `mosaic.ucm.v0.1`, and a signed constitutional change capsule.
The declared collaborator identity must equal the MosaicID derived from the
public key that verifies the signature. Use `publication-receipt-verify` before
trusting a publication record. Create retrieval evidence only from the actual
artifact path and that validated publication receipt; never accept a caller's
claim that the bytes were checked.
Only opaque credential references are portable. Raw secrets, passphrases, and
private keys never enter CLI arguments, journals, capsules, cold boots, or
courthouse packets.

At turn opening, retain the exact dependency graph, snapshot, evaluation,
impact, injected-context text, source roots, and reason paths supplied by
Pippi. Before closing, reconcile those heads. If project, journal, graph,
snapshot, or evaluation drifted, file the refused reconciliation and reopen
from current state. Never use progress JSONL as evidence or let retained
context enlarge the capability ceiling. See
[Dependency and Evidence Graph](docs/DEPENDENCY-AND-EVIDENCE-GRAPH.md).

## Before proposing an effectful Courthouse work order

Orient to `docs/CCP-COURTHOUSE-BOUNDARY.md`. Bind the exact P/PPI acceptance
case and work unit, compile the exact Workflow IR request, build a current CCP
admission envelope, and show the projected status to the user. `CURRENT_ADMIT`
permits only Courthouse preflight. Do not describe it as authority, G1 PASS,
execution, or an installed route. Submit only through the external Courthouse
adapter, and accept a result only when G1 carries the required three CCP roots.

1. Locate the installed `pippi.cmd` or the authenticated local service endpoint.
2. Run `pippi verify` before relying on project or session state.
3. Run `pippi project-brief PROJECT_ID`. Treat its rooted **Now** projection as
   the shared human/agent answer to current state, reason, and the next safe
   navigation context. It never authorizes dispatch.
4. Read the selected project and request an exact context-injection record for
   the current scenario.
5. When present use is conditional, request an exact point-of-use admissibility
   decision and its Pippi projection. The projection answers “Can I use this
   now?” from caller-supplied roots; it neither fetches evidence nor grants
   authority.
6. Preflight the planned record bundle before expensive work or effects.
7. Keep execution holds, release blockers, qualification gaps, and user
   acceptance pending in their own fields.
8. Inspect the integration registry. Treat `DECLARED_UNBOUND` as unavailable,
   even when the owner is named in documentation.
9. Inspect `pack-list`, `pack-inventory`, and the project's portability result.
10. Observe and bind the execution context before shell, filesystem, text,
    packaging, or portability work. Re-observe after transitions and use the
    Windows/WSL correspondence gate for portable claims; do not infer host
    rules from chat memory.
    Do not infer that SemCrys, Memory Vault, Courthouse, native UGK, or a host
    adapter is available from documentation or a nearby archive. Preserve
    missing-pack holds and use explicit external authorization for acquisition.
11. Route local effects through a host adapter bound to the exact UCM Gateway
   policy and remote correspondence through the courthouse. P/PPI does not
   grant either kind of authority. A seven-channel declaration is not an
   `ENFORCED_HOST` attestation.
12. After a material effect, preserve a no-replay capsule and resume from its
   exact journal/process heads.
13. Export causal journal roots and archive references at handoff. Progress JSONL
   is visible telemetry and never evidence.

Use the installed `ucm-pippi-mediated-agent` skill for the full procedure.

## Adaptive turn protocol

r035 enriches this same protocol through optional `turn_details` and explicit report supersession; it does not
require intercepting every tool call. Read [Common turn records and CMBA](docs/PIPPI-COMMON-TURN-RECORDS.md).
`turn-prepare` returns exact reporting requirements and pending-close context;
`turn-report` stores the original report plus its richer record; `turn-reconcile`
can bind that record. Use `pippi turns PROJECT_ID` to inspect the shared journal
projection. A declared basis or a CMBA structural PASS is not verified activity.

1. Run `pippi interface-doctor` and `pippi mediation-library`.
2. Negotiate the actual host through `pippi host-negotiate REQUEST.json`.
   Artifact access alone proves only `ARTIFACT_MEDIATED_WEB`.
3. Open the turn with `pippi turn-prepare REQUEST.json`, binding the exact
   project root, journal head, execution-context capsule, acceptance cases,
   and selected mediation rules.
4. Perform only work allowed by the surrounding host and gateway. The opening
   is context and custody, never effect authority.
5. Close with `pippi turn-report REQUEST.json`, classifying facts as observed,
   derived, agent-reported, user-reported, or unresolved.
6. On a local hub, run `pippi turn-reconcile REQUEST.json` against the current
   project and journal heads. A web-host report remains agent-reported until a
   local reconciliation accepts it.
7. Export a `CONTEXT_ONLY`, `WORK_CAPSULE`, `PROJECT_PORTABLE`,
   `AIRGAP_COMPLETE`, or `FULL_REFERENCE` capsule. Verify it before import.

The capsule contains public identity roots and exact artifact references only.
Private signing material and provider credentials remain outside the archive.

## Manual operator courts

Use `pippi operator-kit-contract` and `pippi operator-kit-verify` when a manual
operator court needs a double-click package. P/PPI governs the reusable kit
envelope; the subject runner owns the actual cases. Building or verifying the
contract never executes the court. The operator decides when to run it.

## External executor packs

Inspect the optional pack registry before proposing external execution. The
`UGEL_EXECUTOR` pack is absent until an exact source and executor-key binding is
recorded. Begin with `ucm ugel-orient` and
`docs/UGEL-EXECUTOR-INTEGRATION.md`. Do not infer availability from a local
folder, let Pippi select an executor, or treat a pack binding as operation
authority. Only the executor named by the external permit signs the G2/G3 input
receipts.
