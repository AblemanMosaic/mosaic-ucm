# Universal Constitutional Machine (UCM) v0.1

Engineering candidate **r035** closes the [common P/PPI turn records and CMBA](docs/PIPPI-COMMON-TURN-RECORDS.md) workflow:
purpose, constitutional context, declared provenance, evidence coverage, acceptance
dispositions and closure in the existing project journal. The optional exact CMBA
wheel supplies structural binding/evaluation/replay over those records. Public
version remains v0.1. This candidate carries scoped positive construction evidence;
its operator adversarial apparatus is supplied separately and unexecuted.

UCM is Ableman Mosaic's portable substrate for **constitutional computing**:
software states what must remain true, which variations are admissible, what
evidence can support a claim, and where authority must come from before an
effect occurs. Humans, agents, courts, and ordinary programs can share those
machine-checkable boundaries without sharing an implementation or surrendering
native authority.

The paradigm shift is from trusting a process because it produced an answer to
checking a constitutional correspondence: exact subject, exact rules, exact
capability ceiling, exact evidence, and exact custody. UCM separates state from
semantic projection, governance from permission, progress from evidence, and
historical validity from present admissibility. It can therefore explain and
continue work across sessions, hosts, languages, storage providers, and agent
runtimes while refusing to turn a hash, a model judgment, or a passing test into
authority it did not receive.

UCM is both a reference runtime and a protocol family. Python supplies the most
portable, inspectable implementation. Small native C slices can independently
verify bounded projections and accelerate mature deterministic kernels. P/PPI
applies UCM to longer-horizon project and process work; AMCAS constitutionalizes
applications; CCP evaluates point-of-use admissibility; the Operational Gateway
receipts effects; THR separates commitment domains; DKN supplies cryptographic
namespace when a real key ceremony binds one.

r033 closes the deployable path for the bounded UCM Native Core profile:
Python authors and evaluates the portable fallback, the canonical projection
runs on a dependency-free C17 VM, and qualification requires exact result
correspondence across a frozen constitutional corpus. The profile covers
bounded integer gates, budgets and typed dispositions; it does not claim that
the full UCL-SH compiler or every UCM subsystem has been translated to C. See
[UCM Native Completion](docs/UCM-NATIVE-COMPLETION.md).

## Transtemporal custody and native verification

r031 adds a P/PPI-governed transtemporal archive for project history. Distinct
bytes are stored once under a BLAKE3-256 content address; every logical file also
carries SHA-256 for interoperable and native verification. Stable integer file
identifiers and immutable revision manifests preserve exact reconstruction,
diff, rollback, and lineage without hauling duplicate release archives through
every runtime. THR records state, semantics, governance, jurisdiction, and
receipt commitments separately. The default `mosaic.ucm.v0.1` DKN namespace is
declared but remains unbound until a real public-key ceremony occurs.

SemCrys and Mosaic Memory Vault are optional realizations. P/PPI can produce a
rooted compression/storage plan, but neither compression nor remote storage is
performed by planning. Restored bytes must pass the original dual-digest
manifest. The small C17 verifier under `native/` independently checks the
SHA-256 projection; it does not claim to replace BLAKE3, THR, DKN, AMCAS, or the
reference verifier. See [Transtemporal Archive and Native Verification](docs/TRANSTEMPORAL-ARCHIVE-AND-NATIVE-VERIFICATION.md).

## Point-of-use admissibility

The CCP-derived point-of-use subsystem answers **“Can I use this now?”** from
an exact, caller-supplied snapshot whose six admissibility statuses are derived
from separately linked evidence rows. It keeps historical validity separate from
present admissibility and can return `ADMIT`, `REFUSE`, `DEFER`, or
`UNRESOLVED`. `EXPLAIN_CURRENT_ADMISSIBILITY` gives Pippi a human projection
of the same rooted decision; it does not create a second decision record.

The evaluator is pure: it does not fetch evidence, read a clock, inspect a
host, grant a capability, or perform an effect. Evidence acquisition remains
an independently authorized operation. An `ADMIT` result becomes relevant to
an effect only through `PREPARE_ADMISSIBILITY_BOUND_GATEWAY`, which rechecks
independent policy, schema, trust, jurisdiction, checkpoint, decision, and
current-use roots before the existing G1/G2/G3 gateway path. The target version
must still be checked before the effect. A merely declared enforcement
perimeter yields `UNRESOLVED`; only an exact `QUALIFIED_SCOPED` perimeter can
participate in `ADMIT`. The snapshot's logical step budget is enforced. See
[CCP source binding and point-of-use admissibility](docs/CCP-ADMISSIBILITY.md).

## Operational gateway

Effectful work crosses a **receipt-mediated gateway**. UCM checks a bounded
permit, records authorization and dispatch intent before the effect, and then
checks the executor's signed dispatch and terminal receipts. UCM does not
select, install, or impersonate an executor.

For application-wide adoption, continue with the
[Constitutional Integration Runtime](docs/CONSTITUTIONAL-INTEGRATION-RUNTIME.md).
It binds UGK, ESA, SRSA, COP, both qualified EVS jurisdictions, native test and
repair planes, fixed-denominator control, portable application capsules, and a
read-only ecosystem observatory around the same gateway. The deterministic
Memory Vault pilot and operator-run court are built by
`tools/build_constitutional_integration_kit.py` and
`tools/build_constitutional_integration_operator_kit.py`.
Start with [docs/OPERATIONAL-GATEWAY.md](docs/OPERATIONAL-GATEWAY.md). Humans
and agents use the same `operational-invoke` CLI and `ucm.invoke` ABI. Every
external effect follows this order:

1. verify the issuer, permit, current revocation registry, identity/session,
   jurisdiction, effects, budget, rollback root, generation, and freshness;
2. append authorization, G1, and dispatch-intent records before any effect;
3. let an independently chosen executor act with the pinned idempotency key;
4. record its signed dispatch and terminal receipts;
5. derive G2, G3, proof obligations, THR commitments, and a portable archive.

The JSONL progress stream and its compact summary are nonsemantic. The journal,
receipts, proof bundle, THR manifest, and archive are semantic custody records.
